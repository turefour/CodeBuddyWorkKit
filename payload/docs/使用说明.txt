============================================================================
 CodeBuddy 工作套件 - 使用说明
============================================================================

一、这个包是什么
----------------------------------------------------------------------------
把四个自研工具和一套 CodeBuddy 规则打成一个可离线部署的包：

  1. CodeVault 索引库        项目索引 / 源码查看 / 仓库状态 / 脚本库（Web）
  2. CodeBuddy Pulse        AI 编程进度看板，含"重复测试进程守护"
  3. Idle Tuner             IDE 空闲降温：回收内存、降优先级、挂起进程
  4. ScriptVault 脚本库      公共模块 + 可复用工具 + 回归测试
  5. 全局规则               让 CodeBuddy 在本机优先复用上面的工具

二、安装步骤
----------------------------------------------------------------------------
  1. 解压本压缩包到任意目录（不要直接在压缩包里双击运行）
  2. 双击 installer.exe
  3. 阅读功能说明 → 点「① 检测环境」
  4. 检测通过后点「② 开始安装」，确认对话框
  5. 等待部署与自检；出现「部署完成」才算装好
  6. 桌面会出现「CodeBuddy 工作套件」快捷方式

安装可选参数：
  · 安装目录：默认 %LOCALAPPDATA%\CodeBuddyWorkKit，建议改到非系统盘
  · 端口：索引库 47910 / 看板 47821 / 降温 47822，被占用就改
  · 允许局域网访问：勾选后监听 0.0.0.0（同事可访问，注意自行控制权限）

三、安装后怎么用
----------------------------------------------------------------------------
  · 双击桌面「CodeBuddy 工作套件」快捷方式
    → 打开的是**独立窗口**（没有地址栏和标签页，看起来像桌面应用）
    → 启动时会自动把索引库服务拉起来
  · 窗口右上角的「最小化」和「关闭」都会**收进右下角托盘**，不会真的退出
  · 双击托盘图标恢复窗口；托盘**右键**有菜单：
      显示主窗口 / 在浏览器打开索引库 / 打开 Pulse / 打开 Tuner
      隐藏到托盘 / 关闭窗口（服务继续运行） / 停止服务并退出
  · 想用浏览器看：右键托盘 →「在浏览器打开索引库」，或直接访问 http://127.0.0.1:47910/
  · 「启动全部服务.cmd」一次拉起三个服务（不带窗口）
  · 「停止全部服务.cmd」停止

  说明：**不会开机自启**。安装过程不写注册表 Run 项，也不放启动文件夹，
       只有在手动双击快捷方式时才会运行。

四、常见问题
----------------------------------------------------------------------------
  Q: 提示环境检测未通过？
  A: 看日志里标记 [阻塞] 的项。最常见的是没有 Node.js（装 18+ 或使用含运行时的包）。

  Q: 端口被占用？
  A: 安装时可改端口；已安装的改 config\deploy.json 后重启。

  Q: 页面打不开？
  A: 先跑「启动全部服务.cmd」；看窗口里的报错。

  Q: 想看重复测试进程的告警？
  A: 打开看板，右上「运行中的脚本」顶部会出现黄/红告警条。

五、卸载 / 回退
----------------------------------------------------------------------------
  运行安装目录里的「一键清理与回退.cmd」，它会：
    1. 停止三个服务（只停本套件端口上的进程）
    2. 删除桌面快捷方式
    3. 删除 ~\.codebuddy\rules\deploy-target.mdc（不碰其它规则）
    4. 删除安装目录

  也可以手动跑：
    powershell -ExecutionPolicy Bypass -File tools\uninstall.ps1 -Target "<安装目录>"

六、目录结构（安装后）
----------------------------------------------------------------------------
  CodeBuddyWorkKit\
    apps\codevault\      索引库
    apps\pulse\          进度看板
    apps\tuner\          降温面板
    apps\scriptvault\    脚本库
    config\deploy.json   端口与监听地址（改这里）
    runtime\             便携 Node / Git（若本包附带）
    state\               运行中的 pid 文件
    启动索引库.cmd
    启动全部服务.cmd
    停止全部服务.cmd
    一键清理与回退.cmd

七、升级与版本检测
----------------------------------------------------------------------------
安装器在点「① 检测环境」时会先查一次安装状态，告诉你三件事：
  · 这台机器有没有装过（读注册表 HKCU\Software\CodeBuddyWorkKit 与目标目录的 deploy.json）
  · 已装的版本、安装时间、装在哪个目录
  · 与本包版本的关系：首次安装 / 同版本重装 / 升级 / 降级

检测结果里会明确列出**已装版本**与**更新日期**：

  已装版本 : 1.0.0
  更新日期 : 2026-11-13 14:00
  安装位置 : C:\Users\xxx\CodeBuddyWorkKit

状态栏会显示成：`升级 v1.0.0（2026-11-13 14:00 部署）→ v1.0.1｜环境检测通过（1 项提示）`

点「② 开始安装」后的确认框还会再列一遍：

  已装版本：v1.0.0
  更新时间：2026-11-13 14:00
  安装位置：C:\Users\xxx\CodeBuddyWorkKit
  本次方式：升级 v1.0.0（2026-11-13 14:00 部署）→ v1.0.1

这样在真正动手之前，就能确认「现在装的是哪个版本、多久之前装的」。

单独查询（不启动安装器）：
  powershell -ExecutionPolicy Bypass -File tools\check-install.ps1 -Target "<安装目录>"
  加 -Json 供脚本解析

  退出码：0 = 未安装    1 = 已装同版本
          2 = 已装旧版（可升级）    3 = 已装新版（降级）

升级行为：端口、监听地址、config 与 data 全部保留，只覆盖应用代码并更新版本号。
降级不阻止，但会在检测结果里标红提示。

八、规则说明
----------------------------------------------------------------------------
安装会写入 ~\.codebuddy\rules\deploy-target.mdc，作用是：

  · 告诉 CodeBuddy 这套东西装在哪、怎么启动
  · 要求优先复用脚本库里的工具，不要临时重造
  · 约定任务收尾自动刷新索引并提交代码
  · 明确禁止把密钥、日志、业务数据提交进仓库

卸载时会自动移除该规则文件。

九、适配其他 AI 编程平台
----------------------------------------------------------------------------
本套件 90% 的部分与平台无关：索引库、Pulse 看板、Tuner 面板、脚本库工具、
部署脚本、托盘窗口、版本检测，都只依赖 HTTP 与命令行，任何平台都能用。

唯一需要"落盘"的是规则正文（告诉 AI 这套东西在哪、工具怎么调）。安装时
tools\install-rules.ps1 会把同一份正文分发到各平台的约定位置：

  平台          落盘位置                              方式
  ------------  ------------------------------------  --------
  CodeBuddy     ~\.codebuddy\rules\deploy-target.mdc   独占文件
  Cursor        ~\.cursor\rules\deploy-target.mdc      独占文件
  Windsurf      ~\.windsurf\rules\deploy-target.md     独占文件
  Claude Code   ~\.claude\CLAUDE.md                    追加区块
  Codex         ~\.codex\AGENTS.md                     追加区块
  Cline         ~\.clinerules                          追加区块
  通用          <安装目录>\AGENTS.md                    追加区块

默认 auto：只为本机已存在的平台目录写（只装了 CodeBuddy 就只写它 + 通用一份）。
强制全写：安装时加 -Platforms all

聚合文件里的内容被 <!-- CodeBuddyWorkKit:BEGIN --> 包裹：
  · 重复安装只替换这一块，不动你的其它内容
  · 卸载时只删这一块，块外的规则原样保留

关于自动化采集（Pulse 的 hook）：
  hook 配置是 CodeBuddy 插件格式，其他平台不会自动加载。但这不影响看板可用：
    · 进程扫描（含重复测试进程守护）与平台无关，照常工作
    · 想拿命令进度可用包装方式：node <安装目录>\apps\pulse\cli\pulse.js run -- <命令>
  Claude Code 这类支持 hooks 的平台，可参照 apps\pulse\hooks\hooks.json
  的事件名（PreToolUse / PostToolUse / Stop）自行接入，回调同一个 pulse-hook.js。
